# Readiness: what stops a newcomer, and a first client system

Walk 1 (the newcomer's walk) was done on 2026-11-15, by reading the repository only. Nothing was started or rebuilt.
Most of what stops a fresh clone is set only in the owner's `.env` or on their host: PyYAML on the host,
`OLLAMA_URL`, a pulled local model, port 8080 free, an x86_64 machine. Tracked files have no absolute home paths.
Substrate's tooling reads one repository, one evidence log and one streams file. A second system can be mapped,
but not yet judged.

## Not checked

- A run from a fresh clone. It needs the owner's stack stopped (finding 11) or another machine, so how long the
  image builds take was not measured. They build four images (db, workbench, graph, tools) and pull eight more.
  What is built locally here is about 1.2 GB; with what is pulled, about 7.5 GB.
- Whether the exact apt versions pinned in `deploy/postgres/Dockerfile:36` can still be installed from
  apt.postgresql.org.
- Whether the pgGraph and Ontop images pinned by digest exist for arm64.
- The Docker path end to end (rule 5: untested by design), macOS, and Podman versions other than 4.9.3.
- What `up.sh` prints when `OPENROUTER_API_KEY` is empty: the two OpenRouter ranks in `streams.yaml` have no
  provider, and whether `streams.sh` reports this cleanly was not seen.
- Whether the gateway starts cleanly when it has no provider at all (no OpenRouter key and no `OLLAMA_URL`).
- How fast the CPU-only Ollama is: the time to embed the map, and whether a judged run of `granite4:3b` fits in
  `morphogen.yaml`'s `timeout: 900` without a GPU.
- Whether `github.com/OpenReplicant/Substrate` and the Morphogen plugin's marketplace can be reached without
  the owner's GitHub account.

agent (S-98). Below is what the tooling assumes, from the code alone. "Real limit" means it cannot work for
another system without a change; "naming" means only the words or defaults assume Substrate.
