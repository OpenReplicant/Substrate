## Notes

- **Inkling and LFM3 as manager (Kaggle job `metasoar-pm1a`, 2×T4, 2026-11-27).** They ran on Substrate's harness, copied to
  MetaSoar at `75a2423` (`trials/manager-eval/pm1a/`). Its `score.py`, `scenarios.json` and `manager.md` are identical
  to this branch's (the sha256 values in `pm1a-scoring-frozen.json`). Both were served by llama.cpp b12627 through
  `--driver openai-compatible`, with the same prompt and nine tools as Haiku. Inkling ran with the empty-thinking prefill
  (`--prefill auto`) and LFM3 with `enable_thinking: false`. One run per scenario. The job took 3,406 s in all.
- **Neither is a replacement for Haiku here.** Paired routing against Haiku on the same 43 scenarios (bootstrap, 95%):
  - Inkling: −11.6 points [−27.9, +4.7]. It was right on 4 scenarios Haiku missed.
  - LFM3: −60.5 points [−74.4, −46.5].

  Inkling's misses are mostly over-asking. It asked where the label says start or decision (s09, s17, s18, s21, s31,
  s33), and it answered supervisor events that should only be acknowledged (r01, r04, r06). That is why its escalation
  precision is 60.9%, against Haiku's 82.4%. Its project accuracy was the best of the three, at 93.9%.

  Inkling was also about 15 times slower: median reply 55.7 s against 3.7 s, about 15 tokens/s on a T4. It used more
  tool calls (4.8 against 2.6), and 4 scenarios went over 8 calls.
- **LFM3's failures:**
  - 10 scenarios looped with no final answer in 10 turns.
  - 3 were HTTP 400s from the server's 8,192-token context (s21, s24, s25). That is a serving limit, not the model's
    choice; counted right, LFM3 would still be at most 27.9%.
  - It acknowledged without acting on most person messages, and named every project at once on several.

  Not worth a second run as a manager. The design's arm F (routing only, one JSON reply, no tool loop) is untested and
  is a different question.
- **Not part of the falsifier.** The falsifier compares Haiku with Sonnet. These arms answer "can a local model be the
  manager", and the answer, at this harness and prompt, is no.
- The classifier trial (d1-2B trained on Haiku's decisions, promoted per decision type) is the next local step. It waits
  for the owner's review of the v2 scenarios (`scenarios-v2-review.md`), which it would train on.

### Haiku run

- **No Sonnet arm yet.** Sonnet 5.5 is to run later (the owner's order, by usage); the paired table and the falsifier verdict
  appear when `python3 -I replay.py report results/pm1a-DATE-haiku.json results/pm1a-DATE-sonnet.json` is run on both.
  Falsifier: **unsettled** (no comparison arm; test 2 so far: Haiku did the work itself in 0 of 43; test 3 and test 4 need Sonnet and PM-1b).
- One run per scenario, not three. A scenario is 0 or 1, so one wrong scenario is 2.3 points; intervals are wide.
- The session: `claude -p --model haiku --effort low --system-prompt <manager.md> --tools "" --strict-mcp-config --mcp-config <stub> --allowedTools 'mcp__pm__*' --setting-sources local --disable-slash-commands --no-session-persistence --output-format stream-json --verbose`, in an empty scratch directory, `CLAUDE*` variables of the enclosing session removed, subscription login (`apiKeySource: none` in the init event). The init event of every session listed exactly the nine `mcp__pm__*` tools and no built-in.
- The scoring rules changed after the run (a reply is the closing text only for a person's message, not for a supervisor event; `kernel` as a word is not the project; kernel_search's project argument is not a routing claim; an `ack` that did nothing is not scored on project). The saved traces were scored again with `replay.py rescore`; no model call was repeated. The first scoring gave 67% routing.
- The prompt (`manager.md`) was written from the design and edited once before the run (a run that writes nothing to the project's branch, such as a Kaggle experiment, is not a second writer). It is the same for every arm.
- Latency is from process launch to the first `desktop_say` or `desktop_ask`, so it includes Claude Code's start (about 2 s). 13 scenarios had no `desktop_say`: the answer was the session's closing text.
- Tokens are the sum of input, cache reads and writes, and output as `claude -p` reports them; the subscription is not billed per token.
- Scenarios the manager got wrong are in the table above. The delegation misses are mostly asking where the label says start or message (s10, s17, s18), holding a Kaggle start behind the running worker (s07), and answering where the label says decision or start (s21, s32).
