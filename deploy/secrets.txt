# The settings that are secrets, read through the secrets slot (SECRETS in .env; `env` is the one backend).
# One per line: name, how scripts/settings.sh makes it when it is missing, and what it is for.
#   token:N        N random bytes, URL-safe text          provided   you give it (empty means not used)
#   key:PREFIX:N   PREFIX plus N random bytes as hex
POSTGRES_PASSWORD           token:24        Postgres superuser
GATEWAY_DB_PASSWORD         token:24        the model gateway's login to its own database (gateway: its config and its log of calls)
GATEWAY_METER_PASSWORD      token:24        the read-only login to the gateway's log of calls (gateway_meter): the meter
GATEWAY_ADMIN_PASSWORD      token:24        the gateway's admin account (its dashboard and API, S-34)
GATEWAY_KEY_SECRET          token:32        derives each caller's virtual key (scripts/gateway.py caller_key)
OPENROUTER_API_KEY          provided        the owner's OpenRouter key (capped by the owner); the gateway reads it, nothing else
STORE_EMBED_KEY             key:sk-bf-:20   the store's key at the gateway for embeddings (local models only)
COMPANION_SESSION_KEY       key:sk-bf-:20   the companion's session's key at the gateway (Anthropic, on the owner's own login; S-136)
COMPANION_TASK_KEY          key:sk-bf-:20   the companion's background tasks' key at the gateway
COMPANION_DB_PASSWORD       token:24        the companion's container's login to the store's database (companion: publish, act, its queues; environment/sql/006)
VOICE_KEY                   key:sk-bf-:20   the voice head's key at the gateway (the local model only: what is said aloud stays on this machine)
COMPANION_AUTHOR_KEY        key:sk-bf-:20   the companion's author of components at the gateway (the local model only: it reads what was said aloud; S-151)
JUDGE_KEY                   key:sk-bf-:20   the judge's key at the gateway (the local model only; S-151)
WORKER_KEY                  key:sk-bf-:20   the worker's key at the gateway (the local model only: an offline agent; S-163)
WORKER_DB_PASSWORD          token:24        the worker's container's login to the store's database (worker: publish, act, its queues; S-163)
WORKER_KERNEL_URL           provided        the worker's kernel login (scripts/up.sh copies it from scripts/kernel.sh login worker; the container cannot read the 0600 file)
JUDGE_DB_PASSWORD           token:24        the judge's login to the store's database (judge: reads the record, records verdicts; environment/sql/007)
SEARXNG_SECRET              token:32        signs SearXNG's sessions (compose service search, S-171)
KK_AUTHENTICATOR_PASSWORD   token:24        the Knowledge Kernel's one login for its services; the UI reads the kernel's read model through it (S-154)
KK_JWT_SECRET               token:32        signs the kernel's tokens for its HTTP MCP (kk token); not used by the stdio profile
