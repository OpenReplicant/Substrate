# Decisions

Append-only, as in kernel's `docs/decisions.md`: a decision changes by a new entry that supersedes it.
Status: **decided** (owner agreed), **adopted** (recommended and taken; confirm or overturn), **open**.

| ID | Decision | Status |
| --- | --- | --- |
| S-01 | **Substrate is an integration, not a new core.** It assembles existing projects into one stack and adds only the glue between them. Kernel stays the world model, Morphogen stays the judge; neither is forked. Each is vendored as a git submodule at a pinned commit (kernel `c23a982`, 2026-10-19; Morphogen `4f36687`, 2026-11-05) | adopted |
| S-02 | **The claims format is kernel's.** One Postgres (kernel D-01) holds every claim: attributed, referenced, belief-scored, scoped, bitemporal (D-09), written only by change sets (D-05), exported as N-Quads (D-45). Graphiti and Cognee are not adopted: kernel already has what they would add (provenance, valid and recorded time, recall by BM25 and embeddings, D-60 and D-61), plus clearance and review, which they lack. A graph engine comes only as a projection where an algorithm pays off (D-08) | adopted |
| S-03 | **The harness is Claude Code.** It fills the cognitive cycle, the builder and the mapper's hands. It reaches kernel through `kk up` (MCP memory profile, skill, hooks; kernel D-57, D-88) and Morphogen through its plugin, installed from GitHub so the judge is never the candidate (Morphogen CLAUDE.md) | adopted |
| S-04 | **The model gateway is Bifrost**, image `maximhq/bifrost:v2.3.2` (transports v2.3.2, 2026-10-20; v2.4.0 and v2.5.0 are under two weeks old). Apache-2.0 (its `LICENSE`, read 2026-11-06). Claude Code reaches it at `/anthropic` with a virtual key, or with a claude.ai subscription plus the key in `x-bf-vk` (Bifrost's `docs/cli-agents/claude-code.mdx`). Why: every model call's tokens and cost are measured outside the agent (Morphogen issue #43) and exposed as Prometheus metrics (`bifrost_cost_total`, `bifrost_input_tokens_total`, `bifrost_output_tokens_total` in its telemetry plugin) | adopted |
| S-05 | **Telemetry goes through Prometheus into kernel.** Prometheus `v3.15.0` at the digest kernel's devops demo pins scrapes Bifrost; kernel's `observer-prometheus` records each window as observed claims (kernel D-52), so cost and errors become claims the MAPE-K loop and Morphogen can both read. Morphogen keeps its own `otel` observer for judged runs | adopted |
| S-06 | **The deployment overlays kernel's compose project.** `deploy/compose.yaml` is an overlay on `vendor/kernel/deploy/compose.yaml`, the way kernel's devops demo is, so `kk up` keeps working unchanged and the substrate adds services beside it. Licences stay kernel's posture (D-11): permissive or LGPL libraries in the default stack | adopted |
| S-07 | **Identity resolution is kernel's M6-T9, judged by Morphogen.** The resolver is a kernel module (Splink, MIT, as M6-T9 names; `skos:exactMatch` when certain, `closeMatch` for review). Morphogen's entity-resolution demo supplies its cells, held-out pairs and verdicts. One resolver, not two | adopted |
| S-08 | **Verdicts become claims.** A new module, `encoder-morphogen`, reads Morphogen's evidence log and submits each verdict as a DQV measurement with PROV lineage, under its own role. Kernel then knows what was judged, by whom, at what cost; Morphogen's log stays the integrity record | adopted |
| S-09 | **The map is kernel's, with Backstage files as a source.** `catalog-info.yaml` describes the substrate (and later, a customer's systems). Morphogen reads it as cells today; a new module, `encoder-backstage`, reads it into kernel as `kk-tosca` claims (kernel D-07). Kernel's UI is the human view; a Backstage server is optional and not in the default stack | adopted |
| S-10 | **First distribution: the system minding itself.** The first thing the stack does is keep a cited, judged model of itself: kernel's self-encoder and the Backstage encoder build the map, Bifrost and Prometheus observe, Morphogen judges changes, `encoder-morphogen` closes the loop. When kernel's distributions land (`kk up --distribution`, kernel D-84 c), substrate becomes one | adopted |

| O-2 | Whether Bifrost stores its logs in kernel's Postgres (a separate database) or its own SQLite volume (default here: its volume) | open |
| S-11 | **Kernel and Morphogen are full clones in `repos/`, not submodules** (supersedes S-01's vendoring; owner, 2026-11-06: "clone the repos ... but be able to contribute upstream as we test fixes"). `scripts/bootstrap.sh` clones each on `main` from `repos.yaml`, which records the commit substrate was last checked against; `repos/` is gitignored. A fix found here goes upstream by branch and PR in that repository (the `upstream` skill); `upstream/<repo>/*.patch` holds fixes prepared but not yet opened | adopted |
| S-12 | **Backstage is in the stack** (supersedes S-09's "optional"; owner, 2026-11-06). Generated with `@backstage/create-app` 0.9.3 (2026-10-20) into `services/backstage`, built by Backstage's host build into `localhost/substrate-backstage:local`, reading `catalog-info.yaml`, in-memory SQLite (the catalog is re-read from files at start). Its generated backend already includes `plugin-mcp-actions-backend`: Claude Code reaches the catalog at `/api/mcp-actions/v1` with a static token limited to `mcp-actions` and `catalog` (backstage.io/docs/ai/mcp-actions). Guest sign-in, local only | adopted |
| S-13 | **Podman by default, Docker by switch** (owner, 2026-11-06). `CONTAINER_ENGINE` in `.env` picks the engine for every script. Kernel's `kk up` calls `docker` directly, so `scripts/up.sh` starts the whole stack itself and calls `kk up --no-stack` for logins and harness wiring; the upstream fix is `upstream/kernel/0001-*.patch` (`KK_CONTAINER_ENGINE`). With Podman, `podman compose` needs the docker-compose provider (or podman-compose) | adopted |
| S-14 | **Gateway providers: Claude, OpenRouter, local** (owner, 2026-11-06). `scripts/render_bifrost.py` writes Bifrost's `config.json` from `.env`: Anthropic always (with an API key if given, else the Claude subscription passed through), OpenRouter if a key is given, Ollama on the host if enabled; one virtual key `substrate` for all of them; auth enforced on inference. The file seeds Bifrost's own config store, so dashboard edits persist. Claude Code is routed by `scripts/gateway.py on` (subscription mode by default: `ANTHROPIC_CUSTOM_HEADERS: x-bf-vk`), applied only after the gateway answers | adopted |
| S-15 | **One `.env` for the stack** at the repository root (mode 600, gitignored), holding kernel's settings and substrate's; secrets are generated by `scripts/up.sh` the first time. Kernel's own `deploy/.env` is not used | adopted |
| O-3 | Whether to open the kernel engine fix (S-13) as a PR now, or after it is tested with Podman on the owner's machine (recommended: after) | open |
| S-16 | **The runtime is a slot** (owner, 2026-11-06: "an opinion that should be swappable"). `RUNTIME` in `.env` names a script in `scripts/runtime/` that defines four verbs, `rt_up`, `rt_down`, `rt_status`, `rt_logs`; `up.sh`, `down.sh`, `logs.sh` and `check.sh` call only those. Two runtimes now: `compose` (kernel's compose project plus `deploy/compose.yaml`) and `nomad` (`deploy/nomad/`). Both read the same `.env`, the same rendered gateway config and the same host folder for kernel's artifacts (`.state/artifacts`), so a project moves between them without re-reading. A third (k3s) is a new file in `scripts/runtime/` plus its manifests | adopted |
| S-17 | **Nomad is the control plane** (owner, 2026-11-06: one control plane across containers, processes and clusters; Nomad "already the right shape"). Chosen over k3s because one scheduler runs containers (Podman or Docker driver), plain processes (`raw_exec`) and later clusters with the same job spec, with built-in service discovery, encrypted Variables, per-task resource limits, Prometheus metrics for allocations, and an ACL'd API a kernel actuator can act through. k3s would give Apache-2.0 and the Kubernetes ecosystem, but processes need adapters and it runs containerd, not Podman. Pins: Nomad 2.0.7 (2026-09-17; 2.1.0 is under two weeks old), `nomad-driver-podman` 0.6.5 (2026-07-13, MPL-2.0; 0.6.6 is under two weeks old; built against Nomad 1.11, confirm it loads on 2.0.7), installed by `scripts/install_hashicorp.py` with SHA-256 checked against HashiCorp's published sums. Single-node agent on 127.0.0.1 (`deploy/nomad/agent.hcl`); one job, five groups (db, kernel, gateway, map, telemetry); host networking on loopback; secrets in one Variable per group with only that group's keys; Prometheus finds targets through Nomad's own service catalog. **Linux only** (the Podman driver is), so `compose` stays the default until `scripts/check.sh` passes on Nomad on the owner's machine; then a new row makes `nomad` the default | adopted |
| S-18 | **Nomad's licence is BUSL-1.1, not open source.** Its additional use grant allows production use except offering Nomad to third parties as a hosted or embedded product that competes with HashiCorp's paid versions; each version becomes MPL-2.0 four years after release (`LICENSE` at v2.0.7, read 2026-11-06). This is outside kernel's D-11 posture (permissive or LGPL in the default stack), which is why Nomad is a runtime choice and not a dependency: nothing in kernel, Morphogen or substrate's modules imports or requires it, and `compose` runs everything without it. Before substrate ships to customers with Nomad inside, the owner decides whether that use is within the grant | open |
| S-19 | **Everything is built and run in containers; the host needs only git, python3 (standard library), the engine (with compose for that runtime) and Claude Code** (owner, 2026-11-06, after bootstrap stopped on a missing gitleaks). Kernel already builds `kk`, `kernel-mcp` and gitleaks into its image; `deploy/tools/Containerfile` adds git and uv 0.13.4 (PyPI, MIT OR Apache-2.0) to make `substrate-tools`. One long-lived container runs it as the host user (`--user`, plus `--userns keep-id` under rootless Podman), on the host network, seeing only this checkout, `~/.config/knowledge-kernel` and the connected projects, each at its host path (`scripts/tools.sh`). The commands in `bin/` exec into it, including kernel's MCP server and hooks that Claude Code starts; `kk up` runs there and `scripts/point_harness.py` rewrites the commands it wrote to `bin/`. Backstage builds in two container stages (`services/backstage/Containerfile`) and hands its `yarn.lock` back. Morphogen's judged runs stay with its plugin on the host (they start sandboxes of their own). Fixes bootstrap's check, which counted "gitleaks" as "git" | adopted |
| O-4 | Upstream to kernel: a `kk up` option naming where its MCP and hook commands live (for example `--commands-dir`), so substrate no longer rewrites them after the fact | open |
| S-20 | **One front door: Caddy, with plugins by listing them** (owner, 2026-11-07: "expand the base stack a little to include Caddy (which can have plugins)"). Kernel's stack already runs Caddy 2.11.7 at 127.0.0.1:8080 (kernel pins `caddy:2.11.7-alpine`; 2.11.8 and 2.11.9 are under two weeks old). Substrate takes over that service with `deploy/caddy/Caddyfile`: kernel's routes unchanged, plus `/console/`; the same file serves both runtimes, with addresses from the environment. Plugins: one pinned Go module per line in `deploy/caddy/plugins.txt`; empty (the default) uses the stock image, otherwise `scripts/build.sh caddy` builds with xcaddy on the official `caddy:<version>-builder-alpine` image and copies the binary onto `caddy:<version>-alpine`, as the image's docs describe. Apache-2.0 | adopted |
| S-21 | **The bus is pgmq in kernel's Postgres, in a database of its own** (owner, 2026-11-07: "maybe PGmq since we're already flying on postgres?"). pgmq v1.13.1 (2026-10-19, commit `8eab182`, PostgreSQL License; v1.13.0 2026-09-07). It is plain SQL, so `deploy/postgres/Containerfile` copies its extension files onto kernel's Postgres image (checked out by tag, verified by commit) and `scripts/bus.py` runs `CREATE EXTENSION pgmq` in database `substrate`, owned by login `substrate_bus`, never in kernel's `kk`. Queues: `triggers`, `owner`, `events` (`deploy/bus/queues.txt`). The bus carries work and notices between parts; facts stay kernel claims written by change sets. Kernel's own LISTEN/NOTIFY path (D-32, D-35) is unchanged; a kernel module that bridges it to the bus would go upstream. Compose drops kernel's `build` of the db service with `!reset` (Compose 2.24+) and runs `localhost/substrate-db:local` | adopted |
| S-22 | **The console: one live page, signed in with a kernel login** (owner, 2026-11-07: "push it with some kind of live/polled data and a simple text user/pass"). `services/console`: a small Starlette app run in kernel's image (no new dependencies; HTTP through the standard library, since kernel's image has `httpx2`, not `httpx`) behind the front door at `/console/`. The name and password are the person's kernel login (`kk person add`; kernel's `/ui/login` checks them with Postgres and returns an 8-hour token), kept in an HttpOnly, SameSite=Strict cookie; every request is checked with kernel's `whoami`, and kernel decides what the person may see and review (invariant 4). No second password store. It polls every 10 s: service health, spend from Prometheus, kernel's review queue (approve or decline through kernel's `review` tool), Morphogen verdicts (its evidence log, read-only), bus depths, the clones' refs, the spec's build plan. Proposing a goal puts a message on the `owner` queue. Alpine.js is kernel's pinned copy (3.17.4), served from the same origin under a strict CSP | adopted |
| S-23 | **The spec lives in the repository and builds itself out while it is there** (owner, 2026-11-07: "add the Substrate spec in such a way that the first run can build it out if left in place"). `docs/spec.md` (the copy sessions follow; the Claude Doc is for discussion) and `docs/build.yaml` (its ten steps, each with status, dependencies, whether it needs the owner, and the check that proves it). A SessionStart hook committed in `.claude/settings.json` (`scripts/spec.py hook`, standard library) names the next step; the `build-out` skill works one step per session, setup first, and stops at the owner's decisions. Deleting `docs/spec.md` stops it | adopted |
