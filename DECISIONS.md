# Decisions

Append-only, as in kernel's `docs/decisions.md`: a decision changes by a new entry that supersedes it.
Status: **decided** (owner agreed), **adopted** (recommended and taken; confirm or overturn), **open**.

| ID | Decision | Status |
| --- | --- | --- |
| S-01 | **Substrate is an integration, not a new core.** It assembles existing projects into one stack and adds only the glue between them. Kernel stays the world model, Morphogen stays the judge; neither is forked. Each is vendored as a git submodule at a pinned commit (kernel `c23a982`, 2026-10-19; Morphogen `4f36687`, 2026-11-05) | adopted |
| S-02 | **The claims format is kernel's.** One Postgres (kernel D-01) holds every claim: attributed, referenced, belief-scored, scoped, bitemporal (D-09), written only by change sets (D-05), exported as N-Quads (D-45). Graphiti and Cognee are not adopted: kernel already has what they would add (provenance, valid and recorded time, recall by BM25 and embeddings, D-60 and D-61), plus clearance and review, which they lack. A graph engine comes only as a projection where an algorithm pays off (D-08) | adopted |
| S-03 | **The harness is Claude Code.** It fills the cognitive cycle, the builder and the mapper's hands. It reaches kernel through `kk up` (MCP memory profile, skill, hooks; kernel D-57, D-88) and Morphogen through its plugin, installed from GitHub so the judge is never the candidate (Morphogen CLAUDE.md) | adopted |
| S-04 | **The model gateway is Bifrost**, image `maximhq/bifrost:v2.3.2` (transports v2.3.2, 2026-10-20; v2.4.0 and v2.5.0 are under two weeks old). Apache-2.0 (its `LICENSE`, read 2026-11-06). Claude Code reaches it at `/anthropic` with a virtual key, or with a claude.ai subscription plus the key in `x-bf-vk` (Bifrost's `docs/cli-agents/claude-code.mdx`). Why: every model call's tokens and cost are measured outside the agent (Morphogen issue #43) and exposed as Prometheus metrics (`bifrost_cost_total`, `bifrost_input_tokens_total`, `bifrost_output_tokens_total` in its telemetry plugin) | adopted |
| S-05 | **Telemetry goes through Prometheus into kernel.** Prometheus `v3.15.0` at the digest kernel's devops demo pins scrapes Bifrost; kernel's `observer-prometheus` records each window as observed claims (kernel D-52), so cost and errors become claims the MAPE-K loop and Morphogen can both read. Morphogen keeps its own `otel` observer for judged runs | adopted |
| S-06 | **The deployment overlays kernel's compose project.** `deploy/compose.yaml` is an overlay on `vendor/kernel/deploy/compose.yaml`, the way kernel's devops demo is, so `kk up` keeps working unchanged and the substrate adds services beside it. Licences stay kernel's posture (D-11): permissive or LGPL libraries in the default stack | adopted |
| S-07 | **Identity resolution is kernel's M6-T9, judged by Morphogen.** The resolver is a kernel module (Splink, MIT, as M6-T9 names; `skos:exactMatch` when certain, `closeMatch` for review). Morphogen's entity-resolution demo supplies its cells, held-out pairs and verdicts. One resolver, not two | adopted |
| S-08 | **Verdicts become claims.** A new module, `encoder-morphogen`, reads Morphogen's evidence log and submits each verdict as a DQV measurement with PROV lineage, under its own role. Kernel then knows what was judged, by whom, at what cost; Morphogen's log stays the integrity record | adopted |
| S-09 | **The map is kernel's, with Backstage files as a source.** `catalog-info.yaml` describes the substrate (and later, a customer's systems). Morphogen reads it as cells today; a new module, `encoder-backstage`, reads it into kernel as `kk-tosca` claims (kernel D-07). Kernel's UI is the human view; a Backstage server is optional and not in the default stack | adopted |
| S-10 | **First distribution: the system minding itself.** The first thing the stack does is keep a cited, judged model of itself: kernel's self-encoder and the Backstage encoder build the map, Bifrost and Prometheus observe, Morphogen judges changes, `encoder-morphogen` closes the loop. When kernel's distributions land (`kk up --distribution`, kernel D-84 c), substrate becomes one | adopted |
| O-1 | Where the repository lives on GitHub (suggested: `OpenReplicant/substrate`) | open |
| O-2 | Whether Bifrost stores its logs in kernel's Postgres (a separate database) or its own SQLite volume (default here: its volume) | open |
